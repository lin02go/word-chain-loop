# Dictionary data

The canonical word list is generated from [SCOWL v2](https://github.com/engramtech/scowl),
the Spell Checker Oriented Word Lists. It includes American, British, Canadian,
and Australian spellings and has three cumulative gameplay tiers: SCOWL 60
(`common`), 70 (`standard`), and 80 (`extended`). The exact upstream Git commit
is recorded in `dictionary-report.json`; a new build must not rely on a moving
branch name.

The aligned metadata has one job per field:

- `WORD_TIERS` controls which difficulty accepts a word.
- `WORD_FORMS` and `WORD_LEMMA_IDS` group inflections so one family cannot be
  reused in a round.
- `WORD_STARTS` controls which canonical lemmas may be selected as openings.
- `WORD_FEATURED` starts from canonical common-tier words (SCOWL 60) and is the
  editorial quality flag used to prefer familiar hints and closing answers. It
  is deliberately independent from the stricter SCOWL 35 start eligibility.

The build excludes abbreviations, contractions, punctuation, digits,
non-ASCII forms, capitalized entries (normally proper names or acronyms), and
SCOWL entries flagged at the default vulgar/offensive levels. Filtering takes
place before lowercasing so a proper name cannot become an ordinary-looking
game word simply by losing its capital letter.

SCOWL's combined work is available under an MIT-like, BSD-compatible license.
The applicable upstream notices are shipped as
`THIRD_PARTY_NOTICES/SCOWL-Copyright.txt`; keep that file when distributing an
updated dictionary.

## Editorial overrides

Reviewed exceptions live in `dictionary-overrides/` rather than in generated
JavaScript. `allow.txt` admits a missing word at a named tier, `deny.txt` removes
an unsuitable entry, and `featured.txt` / `unfeatured.txt` adjust player-facing
quality without changing whether the word is accepted. Each non-comment line
should carry a short source or editorial reason in its comment so a future
reviewer can reproduce the decision.

## Updating the list

1. Check out an immutable SCOWL commit and record its 40-character revision.
2. Review the four override files.
3. Run `python tools/build-dictionary.py --scowl-dir <path-to-scowl-checkout>`.
   For a non-Git source tree, also pass `--source-revision <immutable-id>`.
4. Run `npm run validate:dictionary`, then the full `npm run check`.
5. Commit the canonical `dictionary.js`, both runtime packs,
   `dictionary-report.json`, and any override changes together.

`dictionary-report.json` records the source revision, all material extraction
parameters, override counts, output hashes, and tier counts. The currently
checked-in canonical artifact predates revision capture and is honestly marked
`legacy-unrecorded`; the next upstream rebuild will replace that marker with a
locked commit.

## Runtime packs

`dictionary.js` is the canonical review/build artifact. Browsers initially load
`dictionary-core.js`, containing the common and standard vocabulary plus any
lemma records needed for family checks. `dictionary-extended.js` is parsed only
when Hard mode or a hard campaign level is opened. Both are generated by
`tools/build-dictionary-packs.mjs` and are cached by the service worker, so Hard
mode remains available offline after installation.

The game constructs a separate graph for the active difficulty from the loaded
tiers and checks reachability against words already used in the current round.

## Product policy

The file is an acceptance dictionary, not a promise that every entry is common.
Only quality-controlled canonical entries can become starting words; extended
entries are reserved for harder play. Player-submitted words should enter the
reviewed override layer with a recorded source and approval reason.
